# 从已保存草稿发起 Agent 修订

日期：2026-10-22。用户要求继续开发；在已完成的修订对照基础上，补齐手动草稿及历史草稿的直接修订入口。

## 使用方法

1. 在作业准备页打开本题的“已保存草稿”，或打开刚保存的手动草稿。
2. 点击“让 Agent 修改这份草稿”。页面展开 Agent 面板，读取所选草稿并定位到修改意见输入框。
3. 核对草稿标识、评分点数量和确认状态，填写意见，选择起草配置，点击“按修改意见生成新版”。
4. 新任务生成草稿后，打开它查看与原稿的结构化对照，再决定是否确认。原稿及其固定版本保留。

手动草稿不需要先关联一条 Agent 任务；已确认草稿也可以作为新任务的来源。固定版本详情仍通过“以此起草新版本”先保存草稿，避免把固定版本 ID 当作草稿 ID。点击入口、切换来源和查看对照均不会发起模型调用。

## 状态与接口

- 复用现有 `POST /v1/question-versions/{id}/rubric-agent-runs` 的 `source_draft_id` 和 `instructions`，无新增 API 或数据库迁移。
- 显式选择的草稿优先于面板恢复的历史任务；先读取草稿详情，确认属于当前题目版本，才允许提交。读取失败或题目不匹配时显示错误并禁用修订。
- 所选来源与每份草稿的意见保存在当前页面会话中。切换草稿后再切回，意见仍保留；刷新页面不承诺保留未提交意见。
- “取消草稿选择”只退出来源选择，不取消已经创建的任务。创建成功后清除显式来源并接回新任务，避免下次误用原稿。
- 所有入口共用本题的创建操作。响应丢失时锁定来源选择、意见、起草和历史切换；“重试同一次提交”复用原请求正文和幂等标识。组件重挂载不会用旧成功回执清除后来选择的来源。

后端仍以创建事务内保存的来源快照为准，权限、上下文预算、工具白名单和老师确认规则沿用现有实现。差异比较的语义见 [修订对照](AGENT_REVISION_DIFF_2026-10-22.md)。
