# 修订草稿与原稿的结构化对照

日期：2026-10-22（Asia/Shanghai）。在 [老师反馈驱动的修订](AGENT_REVISION_2026-10-22.md) 之上，补齐“新版到底改了什么”的可见性。本文记录实现、语义边界与验证结果。

## 一、行为

打开一份由 Agent 修订生成、尚未确认的草稿时，页面在“新版完整细则”之前显示“与原稿的修订对照”：

- 修改意见原文；
- 新增 / 移除 / 修改 / 未变化的评分点计数；
- 整体说明、等级选择规则、取整规则的变化（左右并排显示原稿与新版）；
- 评分点顺序调整提示；
- 逐评分点对照：原稿与新版并排，等级按 `ordinal` 展示，变化项标出“新增 / 移除 / 修改”和具体变化字段；
- 未变化评分点默认折叠，可展开核对；新版与原稿完全一致时明确提示“请检查是否满足修改意见”。

对照只读：不改草稿、不确认、不调用模型。普通起草（没有来源草稿）返回 `revision_comparison: null`，页面不显示该区块。

## 二、接口与匹配规则

`GET /v1/rubric-drafts/{id}` 新增 `revision_comparison`：

| 字段 | 内容 |
| --- | --- |
| `run_id` | 生成这份草稿的修订任务 |
| `source` | 来源草稿的 `id / revision / content_hash` |
| `target` | 当前草稿的 `id / revision / content_hash` |
| `feedback` | 创建任务时保存的修改意见 |
| `source_body` | 创建任务时保存的原稿快照 |
| `difference` | `has_changes`、`summary`、`global_fields`、`criterion_order_changed`、`criteria` |

匹配规则：

- 评分点与等级都按 **ID** 配对；ID 改变视为“移除 + 新增”，不按文字猜测同一项。
- 数值统一渲染为两位小数，`maximum_points` / `points` 的 `5` 与 `5.00` 不算变化。
- 等级数组顺序不参与比较，`ordinal` 变化才算顺序变化。
- 逐行给出 `changed_fields`：评分点为 `description / semantic_version / maximum_points / levels`，等级为 `description / points / ordinal`。
- 整体字段变化单独列出；评分点顺序按共同 ID 的相对顺序判断，新增项不会误报为顺序改变。

服务端在同一 REPEATABLE READ 快照内读取草稿、任务和来源快照，只返回当前老师有权访问的草稿数据；来源快照在创建任务时已冻结，之后编辑来源草稿不会改变对照结果。

## 三、语义边界

1. **这是结构差异，不是语义等价判断。** 文字改写但 ID 不变显示为“修改”，系统不判断改得好不好。
2. **不是重新评分。** 对照不触发任何评分、不改变建议分或确认分。
3. **不替代老师确认。** 是否采纳新版仍由老师在草稿页显式确认。
4. **不含字符级 diff。** 只到字段级（描述、分值、等级、顺序），避免把长文本差异渲染成难以阅读的标记。
5. **来源是创建时快照。** 如果来源草稿在创建后被编辑，对照仍使用当时的版本，和 Agent 实际看到的输入一致。

## 五、已知限制

- 模型如果重命名评分点或等级 ID，界面会显示“移除 + 新增”，需要老师逐项核对；这是有意为之，避免错误配对。
- 对照不展示引用、评分结果或学生答案，只针对细则本身。
- 当前仅在浏览器回归的模拟器路径断言了“无差异”提示；真实 DeepSeek 的差异展示已用本机数据检查过接口输出（2 个新增、1 个移除），未做截图验收。
