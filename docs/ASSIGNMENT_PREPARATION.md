## 可从页面完成的流程

连接工作台后，点击侧栏“作业准备”或批次列表的“准备作业”：

1. 新建课程、一个班级和学生名单；或选择已有课程。学号在该课程内唯一，当前录入上限 200 人。
2. 选择班级并创建作业。服务器在创建时固定参与名单，之后按这份名单关联答案。
3. 保存题号、题干、参考答案或课程材料、满分。可以打开已有题目；修改时另存同题号的新版本。
4. 逐点填写评估内容、由低到高的等级描述与对应分值。分项满分合计须等于题目满分。先保存草稿，再查看全文并确认固定版本。
5. 打开并明确选用一份已确认细则。使用逐份录入或结构化粘贴准备答案，点击预览，核对学生、版本和完整原文后导入。
6. 在“创建批次”选择答案的具体提交版本与评估配置，核对题目/细则版本、答案数量及评分点数后建批次。
7. 打开批次进入现有工作台，查看初评进度、补充引用、复核并下载固定快照。

当前一个批次对应一道题目的一个版本、一个固定细则和 1–200 份答案。多题作业按题分别建批次；页面要求每位学生在同一批次选择一个提交版本。选择项跨分页保留，可按提交版本筛选并查看完整原文。

默认选择 `fake-v1`，只演示流程，不做语义评分。真实模型需要后端配置完毕并由老师显式选择；页面提交具体配置 ID。创建批次会让后台 Worker 安排模型调用，弹窗说明可能产生费用；所有结果仍需复核。`ready` 只代表配置完整，不能证明供应商可达、模型权限或评分准确性。

## 版本与导入语义

已确认细则和题目版本保持只读。基于已有细则起草时保留评分点/等级 ID；评分点自身的描述、等级或分值变化会增加其 `semantic_version`。整体说明变化仍产生新的细则版本和内容哈希。编辑器按 `ordinal` 展开等级，不依赖服务器 JSON 数组的排列。

细则保存后还需单独确认；确认后还需明确选用。新版本不会自动替换页面已选择的旧版本。新规则下可以只选择部分答案重新建批次，旧结果保留；当前会评估这些答案的全部评分点，没有承诺只重跑变更点。

结构化粘贴使用以下 JSON 数组。它是现有内部答案契约的网页输入方式，并未确定首个 CSV/Excel 文件格式：

```json
[
  {
    "external_student_id": "001",
    "external_submission_id": "submission-001",
    "source_revision": "initial",
    "answer_text": "  学生原文\r\n第二行😀  "
  }
]
```

- `external_student_id` 必须为固定名单中的完整字符串学号；`"001"` 与 `"1"` 不同。
- `external_submission_id` 可省略，默认 `submission-<学号>`。同一来源的订正应保留来源编号，并更换 `source_revision`。
- 不在名单中的学号、未知字段、同一学生/来源/提交版本的重复项会阻止导入。
- 答案文本不 trim、不改写 Unicode、不替换空行。逐份录入受浏览器文本框换行处理影响；需要明确保留 CRLF 时，在 JSON 中使用 `\r\n` 转义。
- 空字符串是一份明确提交的空白答案。未提交作业的学生不添加答案行，不能自动补空答案。
- 每份原文最多 100000 个 Unicode code point，每次最多 200 份、合计 2000000 个 code point，与后端限制一致。模型可能有更小的请求上限，超限按现有 Worker 规则失败，不静默截断。

预览不写入、不预留数据。前端将成功预览绑定到当次完整请求内容；修改学生、原文、来源或提交版本后清除预览，提交前再次比较内容。服务器在正式导入事务内重新校验，相同来源/版本的相同内容可复用，不同内容返回冲突，不能覆盖旧答案。本页面不录入 `submitted_at`；需要该元数据的集成仍使用 API。

## 可靠性与代码入口

写操作复用已有 `WriteOperation`，发送中或结果未知时锁定相应表单；重试沿用相同 key 和请求内容。收到成功回执后显示结果，使用明确的“另建/另存/另一次导入”入口开始新操作，避免把旧回执当作新保存。

准备表单、选择和写操作保留在页面内存会话，按课程/作业/题目/来源版本分开。站内切页返回可继续，收到延迟回执后可继续下一步；刷新、关闭或退出会清除临时状态。未保存编辑有离开提醒；未知写操作需先处理完再退出。数据库里的已保存草稿和固定版本可重新从列表打开。

| 文件/目录 | 作用 |
| --- | --- |
| `frontend/src/features/preparation/PreparationPage.tsx` | 课程、作业、题目选择与三个准备步骤 |
| `CreationForms.tsx` | 课程/班级/名单、作业与题目版本创建 |
| `RubricEditor.tsx`、`RubricPanel.tsx` | 分项编辑、草稿查看、确认与固定版本选择 |
| `AnswerImport.tsx`、`BatchCreator.tsx` | 原文预览导入、答案版本选择、固定配置建批次 |
| `contracts.ts`、`session.ts` | 分值及导入约束、预览绑定、会话内编辑状态 |
| `backend/src/teaching_assistant/listings.py`、`listing_api.py` | 新增作业详情及其固定名单查询 |

新增只读接口 `GET /v1/assignments/{assignment_id}`，在老师授权范围和同一只读快照内返回作业、课程/班级名称与 `roster: [{id, external_id, name}]`。成员集合来自 `assignment_members`，不从当前 `memberships` 推算。学生名称与学号是当前学生记录的显示字段，本次未引入姓名历史版本。
