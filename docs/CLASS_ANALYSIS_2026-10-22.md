# 班级学情分析交付

日期：2026-10-22。

沿最初“初评 → 老师确认 → 班级共性问题 → 讲评和十分钟补练 → 订正 → 检查改善”的主线，本轮实现老师确认结果的统计与答案回看，为后续讲评提供可追溯依据。

## 页面使用

打开“作业与复核”中的一个批次，切到“班级学情”：

1. 查看纳入统计人数、确认均分、最低/最高分、确认覆盖率和分数分布。
2. 查看固定名单、未选入本批次、待复核、初评未完成和失败人数。
3. 各评分点按未得满分人数降序展示；点击“查看本项未得满分答案”，阅读对应等级与老师复核理由。
4. 点击学生或“查看原答案”进入已有复核页。修改并保存后返回，会回到分析标签并重新计算。
5. “分析答案范围”可查看全部所选答案或某一状态；切换明细筛选不会改变上方统计分母。跨页面修改复核时，点击“刷新分析”同步概览与明细。

未确认样本为空时均分显示“—”；老师实际确认的零分显示“0.00”。当前页面是一次读取的分析视图，不是冻结导出，既有导出快照仍可用于保留当时记录。

## 统计口径

| 项目 | 口径 |
| --- | --- |
| 范围 | 本批次固定的题目版本、细则版本和所选答案版本 |
| 人数 | 创建批次时已有“每名学生一个答案版本”约束；明确选择新版，不自动回退到已确认的旧答案 |
| 成绩来源 | 初评完成且存在与 `review_revision` 对应的当前老师复核；不使用模型建议分 |
| 确认覆盖率 | 纳入统计人数 / 本批次所选学生人数 |
| 均分与分布 | 仅采用纳入统计的老师确认分数；待复核、失败和未选入批次不填零 |
| 固定名单 | 来自 `assignment_members`，不是当前班级成员关系；“未选入本批次”不推断为未交作业 |
| 分项平均分 | SQL 按当前复核的评分点/等级计数，按该固定细则的 Decimal 分值计算；零权重评分点得分率为空 |
| 未得满分 | 当前确认等级的分值小于该评分点满分；仅作为讲评线索，不自动判定错因或知识掌握程度 |
| 分数区间 | 低于满分 60%、60% 至不足 80%、80% 至不足 100%、满分；不附加及格或掌握等级含义 |
| 精度 | Decimal / PostgreSQL numeric，显示采用两位小数、四舍五入；区间判断使用未舍入值 |
| 模拟标识 | 从固定评估配置 manifest 读取，单列纳入统计的模拟初评人数 |
| 时间 | 显示分析读取时间及所含当前复核的时间范围；不按原始分数变化推断跨次进步 |

同一条初评结果被多个批次复用时，每个批次只分析自己的关联集合。老师有多次复核时，只计当前版本一次。不同细则或不同答案版本的旧结果不会加入当前批次统计。

## 读取接口与一致性

所有接口沿用当前 Bearer 身份和老师对象范围；无权限返回 404，未认证返回 401。不调用模型，不写成绩，也不创建 Agent 任务。

### `GET /v1/grading-batches/{batch_id}/analysis`

返回 `schema_version=batch-analysis-v1`、`snapshot_at`、`basis_hash`，以及：

- `scope`：作业/班级、题目/细则版本、细则摘要、满分、选择规则 `single-answer-current-confirmed-review-v1`。
- `coverage`：固定名单、批次答案/学生数、`confirmed / pending_review / failed / in_progress`、`not_in_batch`、`simulated_confirmed` 和 `confirmed_rate`。
- `scores`：确认均分、最低/最高分、所含复核时间范围和四个分数区间人数。
- `criteria`：评分点说明、满分、确认样本量、均分、得分率、未满分人数/占比和各等级人数；稳定排序保留并列项在原细则中的顺序。

### `GET /v1/grading-batches/{batch_id}/analysis/students`

返回既有 `items / total / limit / has_more / next_cursor` 分页结构，以及 `basis_hash`。

筛选参数：

- `status`：`confirmed / pending_review / failed / in_progress`；省略则返回全部所选答案。
- `criterion_id`：本固定细则中的评分点；指定时仅查询已确认记录，并返回 `level_id / review_reason`。
- `below_full_credit`：需要同时指定评分点，筛选未得满分的确认结果。
- `basis_hash`：概览的来源摘要；前端始终传递，用于阻止人数和答案来源发生错配。
- 通用 `limit / cursor / created_from / created_to`：时间筛选针对初评项创建时间，仅影响明细，不表示按复核时间重算概览。

每行返回学生、所选答案版本、初评项 ID/状态、是否计入统计、确认分数、复核 ID/修订号/时间、模拟标识。打开原答案复用现有 `grading-items` 详情和复核入口。

概览和每次明细查询各自在 `REPEATABLE READ` 事务中完成权限、版本与指标读取。来源摘要包含固定批次/细则以及所选项的状态和当前复核修订号。两次请求间来源变化时，明细返回 `409 / analysis_changed`，页面隐藏失配明细并提示刷新；不会把两次请求伪装成同一个长期快照。游标绑定老师、批次及全部筛选条件，参数错误或游标跨范围使用返回 422。

## 启用与后续

数据库保持 `0006`，重启 API 并使用最新前端即可看到“班级学情”，无需运行新迁移。单独读取分析不需要 Worker；处理未完成初评仍需原 Worker。

下一段是基于这些固定统计和原答案证据生成可供老师审阅的讲评与十分钟补练草稿，再接订正记录与改善核验。本轮未实现语义错因归纳、补练生成或订正闭环，也未使用统计结果改变独立评分规则。
