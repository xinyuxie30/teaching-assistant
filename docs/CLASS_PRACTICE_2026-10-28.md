# 班级历史驱动的题库补练

本轮接通全班统一补练：教师选择班级历史批次 → 读取已确认评分点统计和有效课程记忆 → 检索课程题库 → Agent 选题并解释安排 → 保存独立草稿 → 教师确认。独立评分流程不读取学生历史。

## 使用

1. 在已有“作业准备 / 作业与复核”流程完成至少一份教师复核。所选批次应有已确认的未满分评分点。
2. 打开侧栏“针对性补练”，选择课程和班级。
3. 在“课程题库”录入题干、参考答案、知识点、年级、难度、题型和合法来源。支持单题或每批 1–100 题的 JSON 数组导入。导入结果先待确认，查看后点击“确认入库”。
4. 可在“课程记忆”录入并确认课程共用经验。检索只取已确认、有效且未撤销的记忆，最多 5 条；关键词留空时取最近记录。现有记忆 API 的有效期、替代和撤销规则继续适用。
5. 在“班级补练”选择 1–10 个历史批次，按需筛选年级、难度、题型，填写补充知识点和本次要求。题数为 1–5。
6. 点击“检索适配题目”，检查每个批次的确认覆盖率、评分点线索、题目来源和匹配依据。可勾选恰好指定数量的题目，或不勾选让 Agent 从候选中选择。
7. 选择模拟模式或已配置的 DeepSeek，生成补练草稿。需要后台 `harness-worker`。草稿生成后由教师显式确认；调整要求或选题后可重新检索并生成独立新稿，原稿保留。

默认 `fake-class-practice-v1` 按检索顺序选题，只验证流程。`deepseek-class-practice-v1` 复用现有真实模型适配器，需显式选择；本轮未发起付费模型调用，未评估真实教学效果。

## 检索与证据

- 仅读取当前教师、当前班级所选批次中的最新已确认复核。未确认、失败结果不作为零分或薄弱点。
- 同一作业的同一题目只允许选择一个批次，包括不同题目/细则版本，防止重复计数。不同批次按独立样本保留，不合并为唯一学生人数，也不推断成绩进步。
- 未满分表示可供教师选择的讲评线索；不自动归因为概念错误。模型上下文含评分点统计和等级描述，不包含学生 ID、姓名或答案原文。
- 题库以教师和课程隔离，数据库保护题目正文和来源不可变。内容相同的重复导入复用同一条；修改通过新内容创建新记录，旧题可停用，不能修改或删除历史。
- 检索先严格筛选年级、难度、题型，再以评分点描述的英文词项 / 中文二字片段进行匹配。教师指定知识点的完整子串匹配会加权；课程记忆仅辅助排序，不能独立使一题入选。
- 每个候选附匹配的评分点 ID、词项、教师知识点和记忆 ID。筛选后最多扫描 2000 条有效题目，超过时要求缩小筛选，不能静默截掉；返回前 20 个候选。
- 这是可追溯的词项与结构化检索增强流程，不是向量语义检索；中文近义表达可能漏召回，通用词可能误匹配，需教师审查。无匹配题或题目数量不足时不生成伪造题目来源。
- 预览哈希绑定请求条件、统计版本、有效记忆和候选题。创建任务时在一致快照内重查，来源变化返回 409，要求重新预览。
- 创建任务后输入冻结；后来的复核、记忆撤销和题目停用不追溯改写旧任务。新检索受新状态影响，已有草稿明确展示其历史快照。

## Agent 与权限

新任务类型 `class-practice` 注册两个工具：

| 工具 | 作用 |
| --- | --- |
| `read_class_practice_context` | 读取已冻结的班级聚合证据、课程记忆和检索候选 |
| `propose_class_practice` | 选择指定数量的候选 ID，给出理由和安排，保存未确认草稿 |

服务端复制原题干、答案和来源，模型不能提交替换题目正文；保存时检查候选 ID、数量、去重及记忆引用。停止及教师确认时再次重建校验产物。模型自由生成的理由和安排仍是建议，不等同于已验证教学判断。

复用 Harness 的任务领取、幂等创建、持久消息、预算、取消和教师确认机制。该任务不委派子任务，不扩展原批改或评分细则 Agent 的权限。固定调用上限为模型 6 次、工具 8 次、执行 300 秒，并服从部署模型预算；材料过长时在创建请求预检中拒绝。

## API

| 方法与路径 | 用途 |
| --- | --- |
| `GET /v1/courses/{id}/practice-questions` | 分页题库，包含待确认和已停用记录 |
| `POST /v1/courses/{id}/practice-questions` | 导入 `questions` 数组 |
| `POST /v1/courses/{id}/practice-questions/{question_id}/confirm` | 根据所见内容哈希确认入库 |
| `POST /v1/courses/{id}/practice-questions/{question_id}/retire` | 根据哈希停用题目 |
| `GET /v1/classrooms/{id}/practice-batches` | 分页列出本班可选历史批次 |
| `POST /v1/classrooms/{id}/practice-runs/preview` | 只读检索预览，返回 `preview_hash` |
| `POST /v1/classrooms/{id}/practice-runs` | 使用预览哈希创建持久任务 |
| `GET /v1/classrooms/{id}/practice-runs` | 分页查询本班补练历史 |
| `GET /v1/agent-runs/{id}`、`/{id}/artifact` | 查询任务与草稿 |
| `POST /v1/agent-runs/{id}/confirm`、`/{id}/cancel` | 复用教师确认和取消入口 |

全部入口需要身份认证，所有写操作需 `Idempotency-Key`。响应未知时前端保留原 key 和原请求并提供重试；不能用修改后的请求代替未知操作。

示例题库记录：

```json
{
  "questions": [{
    "title": "解释统一规则的作用",
    "prompt": "为什么评估时要固定规则，并保留历史版本？",
    "expected_answer": "固定规则使评估一致，历史版本支持追溯与复核。",
    "knowledge_points": ["统一规则", "历史追溯"],
    "grade": "七年级",
    "difficulty": "basic",
    "question_type": "简答题",
    "source": "教师自编示例，需按实际课程审查"
  }]
}
```

## 迁移与验证

代码需要新增迁移 `0013`，创建不可变课程题库表。历史 Agent 输入和产物沿用原表，不改变现有评分数据。迁移回退会拒绝丢弃已有题库或补练历史。

在健康的目标数据库上先备份，再执行 `uv run --frozen alembic upgrade head`，重启 API 和 Harness Worker，前端重新构建。不要用 ORM `create_all` 替代迁移。

本轮原本机 PostgreSQL 临时实例报缺失数据文件，连 template0 文件也缺失。未修复、重建或迁移原业务库；从项目已有 PostgreSQL 安装包建立了另一个仅回环监听的临时测试实例，在每个随机测试 schema 内验收。

正式回归入口：

```powershell
uv run --frozen pytest backend/tests/test_class_practice.py -q
npm.cmd --prefix frontend run build
npm.cmd --prefix frontend test
uv run --frozen pytest backend/tests/class_practice_browser_check.py -q
```

后端和浏览器测试均要求 `TA_TEST_DATABASE_URL` 指向专用 `_test` 库。浏览器检查默认使用已安装 Chrome，亦支持 `TA_E2E_BROWSER_PATH`；测试自动启动独立端口 API/Vite 和模拟 Worker，结束后清理进程与测试 schema。浏览器截图和报告在 `.local/e2e/class-practice/`。

本轮验证结果在实施记录中列出。工程验收不证明召回质量、真实模型教学质量或长期容量；暂不包括个人补练、向量索引、图片 OCR、外部联网题库及学生订正效果跟踪。
