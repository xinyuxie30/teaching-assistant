# Harness 真实 API 并发与恢复验收

日期：2026-10-23。用户要求继续使用真实 API 检查多 Worker、子 Agent 调度、中断恢复、未知调用、预算和重复执行。本轮六个场景全部通过；之前的模拟模型持续压测另见 [持续压测记录](RUNTIME_STRESS_2026-10-23.md)。

## 范围与本轮改动

新增 [真实恢复验收入口](../backend/tools/verify_harness_recovery_real.py)、[独立 Worker](../backend/tools/real_recovery_worker.py) 和 [共享调用闸门](../backend/tools/real_recovery_guard.py)。三个独立进程复用生产 Harness 的领取、租约、模型适配器、子任务调度、预算和事务回执；故障点只在验收 Worker 中插入。输入为合成课程，产物保持待教师确认。

发现原真实验收脚本的 `CallGuard` 只保护同一个进程，不能直接用于多进程故障演练。本轮补上本地、跨进程的持久闸门：发起 HTTP 前事务性预留调用次数和费用；拒绝相同 `(run_id, dispatch_sequence)` 再次发送；重开 ledger 或更换 Worker 不能重置限额；未知用量保留全部预留，已知回执不可覆盖。SQLite 文件仅用于验收费用保护，独立于被切断的 PostgreSQL 连接；应用主存储仍是 PostgreSQL，没有新增业务迁移。

请求发送观察器区分代理 `CONNECT` 与真正的模型 `POST`，只在后者请求体发送完成后触发强杀点，避免把代理建连误报成已发送模型请求。日志不记录密钥、请求头或数据库地址。新增 7 项自动测试覆盖多进程抢占同一调用/费用额度、重启保留未知调用、回执冲突、一次性故障点及代理发送观察。

本轮未发现需要继续修改生产 Harness 的新缺陷；前轮的租约隔离、根任务预算锁、事务回执和子任务恢复修复通过了此次真实 API 演练。

## 真实执行

报告标识：`dddb8711-4240-40f2-8c50-5fe3949f4328`。总耗时 **252.64 秒**，始终保持三个独立 Worker 槽位，五次强杀后补充进程，累计创建八个 Worker 进程。另一次故障切断三个 Worker 的私有数据库连接约两秒。只迁移专用 `_test` 库的随机 schema，结束后所有进程、代理、连接和 schema 均已清理。

模型为官方 `deepseek-flash`。实际发出 **28 次 HTTP 请求**，25 次收到返回模型、唯一 request ID 与完整 usage，三次在请求体发出后被强杀、结果未知。请求时间区间证明不同进程存在重叠的真实模型调用，峰值并发为 3，也有子任务之间的重叠调用。

| 场景 | 模型调用 | 运行时未知回执 | 结果 |
| --- | ---: | ---: | --- |
| 并行任务与两层子任务，设计子任务响应收到但未落库时强杀 | 11 | 1 | 父任务及三个子任务完成交接，根任务等待教师确认 |
| 同时执行后台 spawn、一次状态查询及 join | 7 | 0 | 子任务完成，父任务保存方案并等待确认 |
| 请求体发出后强杀 | 3 | 1 | 旧调用保留未知预留，新调用恢复任务 |
| 最后一次模型回执提交后、工具执行前强杀 | 2 | 0 | 复用已提交回执，调用数保持 2，没有重发模型请求 |
| 响应收到后断开数据库，回执未能落库 | 3 | 1 | 重连后恢复并保存唯一产物 |
| 连续两次请求体发出后强杀，根调用上限设为 2 | 2 | 2 | 按预期以 `agent_model_budget_exhausted` 停止，没有第三次请求或产物 |

总计六个根任务、四个子任务。五个根任务等待教师确认，四个子任务完成，另一个根任务按预期因预算耗尽失败；九个有效产物均只有一份且未自动确认。逐项检查了事件序号连续、每次 dispatch 只有一个终态回执、工具请求与结果一一配对、父子调用计数相加等于根计数、哈希一致、结束后无残留租约与待执行调用。

恢复耗时包含配置的 **35 秒租约等待**：子任务响应丢失后整树完成约 49.06 秒；请求发出后强杀约 40.12 秒；已提交响应复用约 35.22 秒；数据库重连后约 36.69 秒。它们是本次小样本测量，不是服务 SLA。

## 未知调用与费用

全进程共享上限为 **36 次调用、0.30 美元**，重启不重置。按当天核对的 [DeepSeek 官方价格](https://api-docs.deepseek.com/quick_start/pricing/)，使用固定峰值费率：每百万输入未命中缓存 0.30 美元、缓存命中 0.006 美元、输出 1.20 美元；配置版本继续冻结为 `deepseek-flash-2026-10-22-peak-ceiling`。

25 份独立观察到的已知回执共 **30,767 input / 5,673 output tokens**，其中缓存命中 22,656 input tokens。独立费用闸门按未命中缓存费率保守核算已知响应，并为三次完全未知响应保留 **0.01190790 美元**，总记账 **0.02794560 美元**。这是固定费率估算与预留，不是供应商账单。

业务运行时有 **五次未知回执**：除上述三次请求发出后强杀，还包括子任务响应未提交、数据库断连未提交这两次。独立验收器虽然已观察到它们的 usage，业务运行时未收到持久回执，不能据此擅自释放预算。运行时总计 70,586 个记账 tokens，其中未知预留 35,947；按冻结的缓存费率和全部未知预留，总记账 **0.029008428 美元**。逐根任务从 usage、冻结价格和预留独立重算，均与预算 API 一致且未超过额度。

额外审计发现四组相同请求哈希的再次发送；它们的前次运行时回执全部为 `model_unknown`。没有重新发送已提交成功回执对应的请求。未知调用可能已在供应商侧执行或计费，恢复时重发同一上下文是显式重试，无法保证供应商侧“恰好一次”。本轮证明的是未知调用不隐去、不退回额度，已提交回执复用，以及有效工具结果和产物不重复。
