# Harness v4：主动问答、确认记忆与单进程并发

本文保留 v4 阶段记录。结果引用、token/费用预留、后台 join、Hook 快照、SSE 及真实 API 验收的后续进展见 [Harness v5](HARNESS_V5_2026-10-22.md)。

本轮重新对照最初的 [架构设计](ARCHITECTURE_REVIEW.md)、[实施计划](IMPLEMENTATION_PLAN.md) 和本地 Claude Code 参考树，补齐了模型主动提出问题后的持久等待、课程范围的确认记忆、单进程多执行槽，以及正常工具循环中的叙述压缩。同时修复模型响应已收到、业务验收拒收时丢失已知用量的审计问题。v3 的并行子任务、共享预算、取消、检查点和定时唤醒继续适用。

这是有明确任务目录和权限边界的教学 Harness。下文区分实际实现与尚未完成的能力，不以模拟流程通过代替真实模型质量或 Claude Code 完整复现。最新验收结果见 [工程实施记录](IMPLEMENTATION_STATUS.md)。

## 模型主动问答

`ask_teacher` 的输入只有问题和可选建议项，没有模型可填写的回答、身份或授权字段。问题最长 1000 字符；建议项为 2–4 项且不能重复。代码注册的工具返回 `TeacherInputRequest`，运行时校验它与原始 tool call 的参数完全对应后，保存不可变等待快照。

只有具备固定 `teacher-questions-v1` 能力的根任务可以提问。等待释放租约、增加 epoch，并冻结剩余执行时间；问题等待不能附加定时器，也不能由心跳、子 Agent 或模型自动回答。读取问题及提交回答都要求当前任务所属教师的认证身份。开发环境的 Bearer 令牌仍是现有本地身份机制，不意味着已经具备生产级组织身份系统。

教师通过当前等待 token 提交非空回答，最长 4000 字符。回答不做 trim 或截断，空白判断只用于拒绝全空白输入。等待 token 对应唯一唤醒回执；重复相同请求可重放，冲突回答、旧 token 和取消后的回答会被拒绝。Worker 恢复后重新检查授权、问题快照及回执哈希，将回答作为原 `ask_teacher` 调用的工具结果写入，随后继续模型循环。接收答案不重复扣除提问工具预算，也不会把同一答案重复插入对话。

问题回答是任务所需的信息，不能替代课程权限、记忆确认、草稿确认或成绩确认。产物仍以未确认草稿保存。若一条模型回复同时提出问题和旧的写入要求，收到新回答后，后续旧写入会被关闭并留下配对错误回执，再由模型依据回答提出新方案。

原有教师主动 `/wait` 与 `/wake` 保留：普通暂停可以没有回答，也可以设置未来的 `wake_at`；模型问题等待必须收到真实回答。这两种路径共享持久等待与租约恢复机制，不能互相绕过约束。

教师主动暂停后补充的新反馈，也会使尚未执行的旧 `ask_teacher` 调用失效。运行时先以 `teacher_input_changed` 配对关闭旧提问、写入或委派，再注入教师反馈，避免模型根据过时要求重复提问。已经持久等待的问题则使用其当前 token 回答。

现有 `AgentPanel` 已能展示 `wait.question`、填写答案、采用建议项，并以原幂等请求重试提交；它继续校验当前题目、任务和等待身份。新课程备课任务尚无专用页面，创建备课、管理课程记忆及操作这些备课任务目前通过 API 使用。

## 教师确认的课程记忆

`teaching_memories` 保存教师、课程、类型、正文、来源、内容哈希、有效区间、确认时间、撤销时间和替代关系。类型为偏好、经验、资料引用。来源可以是教师说明，也可以是同一课程中已经由教师确认的备课产物；系统检查来源身份、课程和产物哈希。

新记忆先以未确认状态创建。教师确认时必须提交所见版本的 `content_hash`；正文和来源不能原地修改。更新通过新记录的 `supersedes_id` 表达，确认新版本时在同一事务中撤销旧版本。撤销要求版本哈希和原因，历史记录保留。数据库约束和触发器限制范围、初始状态以及确认、撤销后的不可改写字段。

只有教师 API 提供创建、确认和撤销入口。模型目录没有记忆写入或确认工具。`lesson-plan-assisted` 的 `search_teaching_memory` 从服务端绑定教师和课程，按文字子串检索，每次最多返回 5 条已经确认、当前生效、未撤销的记录。查询内容不能指定别的教师、课程或提升返回条数。当前实现使用 PostgreSQL 普通查询，没有向量索引或自动语义召回。

备课运行保存实际检索结果及检索时间快照，草稿的 `memory_references` 必须对应最近读取快照中的 ID 与内容哈希。记忆是有来源的参考数据，不能覆盖本次明确要求、固定目标、时长或权限。记忆撤销、到期影响后续检索；已经写入运行历史的读取快照和历史草稿不会被追溯改写，已读取任务也不会被自动重新执行。教师可以取消任务或明确要求重新读取。

固定批改和 rubric 任务没有该检索工具，也不会自动注入课程记忆。学生历史、成绩或画像不进入本次独立评分上下文。这里实现的是受控课程知识复用，不是模型自行形成并写回个人记忆。

## 单进程执行池

`harness-worker` 与兼容别名 `agent-worker` 支持 `--concurrency 1..16`，默认值为 1：

```powershell
uv run --frozen teaching-assistant harness-worker --concurrency 2
uv run --frozen teaching-assistant harness-worker --drain --concurrency 2
uv run --frozen teaching-assistant harness-worker --once --concurrency 2
```

每个槽使用独立 Worker、租约 owner 和数据库会话。空闲槽可以领取另一个槽创建的子任务；父任务等待子任务时释放槽。原有整树锁、epoch、共享预算和固定策略继续生效。进程槽上限与树内子任务上限分别生效：增加到 16 个进程槽不会放宽当前策略中每树最多 2 个正在运行的子任务，也不会放宽最大深度 2 和累计子任务 8 的约束。

`--drain` 持续处理本进程运行期间新出现的当前可领取工作，包括动态子树和祖先汇总；当前没有可领取工作和在途执行后退出，不常驻等待未来定时器或教师回答。`--once` 每槽只做一次初始领取，不复用完成槽或初始空槽来继续清空队列。常驻模式继续轮询到期待办。

进程取消会取消本地模型协程，但保留已经提交的调用预算预留和持久租约。后续进程在租约过期后恢复，未知外部调用记为 `model_unknown`，不会退回调用额度，也不会承诺外部供应商只收费一次。

## 工具叙述摘要与拒收审计

上一版 `semantic-assistant-history-v1` 只摘要独立 assistant 文本。正常循环的解释常常与 `tool_calls` 在同一条 assistant 消息中，之前无法进入该摘要路径。v4 使用 `semantic-tool-narration-v2`：先执行确定性压缩，仍超预算时，可以摘要旧的完整工具组内的 `assistant.content`。

摘要请求只包含候选叙述及原消息来源索引、哈希，不包含工具调用参数或工具结果。恢复后的投影保留原 `tool_calls`、参数字符串和全部未被既有确定性规则删除的工具回执；system/user 消息、固定教学事实、近期消息、最近两组工具交互及未完成组仍受保护。新检查点固定协议版本，校验来源、顺序、响应版本和实际字符节省。摘要不能增加权限或冒充教师事实。

完整历史不被覆盖。摘要使用同一模型适配器，计入局部及整树调用预算；检查点提交后重启不会为同一批内容重复摘要。旧 v3、v2、v1 和原细则策略仍保留对应恢复行为，旧运行不会自动切换到新摘要或新增工具。测试包含正常 Worker 多轮模型工具调用产生长叙述、触发摘要、租约过期恢复和最终草稿，不只依赖手工注入历史。

`save_reply` 另修复了响应已返回后的拒收审计：当课程授权已撤销或业务验收失败，业务成功事件随事务回滚，但失败回执仍保留已知 usage、返回模型、request ID、fingerprint 与 HTTP 状态。没有接受该业务结果，不应被记成外部调用用量完全未知。网络失联等确实无法确定结局的情况继续使用未知调用记录。

## API 示例

以下是接口形状示例。将 `{course_id}`、`{memory_id}`、`{run_id}`、`<content_hash>`、`<wait_token>` 替换为实际响应值。所有请求携带现有 `Authorization: Bearer <token>`，所有 POST 携带 `Idempotency-Key`；每个不同写操作使用独立 key，重试同一操作保持原 key 和请求内容。

创建一条尚未确认的课程偏好：

```http
POST /v1/courses/{course_id}/teaching-memories
Content-Type: application/json

{
  "kind": "preference",
  "title": "课堂交流顺序",
  "body": "先安排独立思考，再进行同伴交流。",
  "source": {"kind": "teacher_note", "note": "教师明确记录的课堂组织偏好"}
}
```

确认、检索与撤销分别调用：

```http
POST /v1/courses/{course_id}/teaching-memories/{memory_id}/confirm
Content-Type: application/json

{"content_hash":"<content_hash>"}
```

```http
GET /v1/courses/{course_id}/teaching-memories?query=课堂&limit=5
GET /v1/courses/{course_id}/teaching-memories/{memory_id}
```

```http
POST /v1/courses/{course_id}/teaching-memories/{memory_id}/revoke
Content-Type: application/json

{"content_hash":"<content_hash>","reason":"教师决定不再采用此偏好"}
```

创建接口还支持带时区的 `valid_from`、`valid_until` 和显式 `supersedes_id`。来源为确认产物时，`source.kind` 使用 `confirmed_agent_artifact`，同时提交 `artifact_id` 和说明 `note`；模型输出本身不会自动成为已确认来源。

新增备课任务通过原课程入口创建：

```http
POST /v1/courses/{course_id}/lesson-agent-runs
Content-Type: application/json

{
  "agent_profile": "fake-assisted-lesson-agent-v1",
  "instructions": "依据简报和已确认课程经验起草方案；信息不足时向我提问。",
  "brief": {
    "topic": "固定记录与可追溯来源",
    "objectives": ["说明为什么需要保留版本与来源"],
    "duration_minutes": 20
  }
}
```

`GET /v1/agent-profiles?task_type=lesson-plan-assisted` 查询 fake 与 DeepSeek 配置可用性。fake 为流程验收固定执行“读取简报 → 检索记忆 → 提问 → 根据真实回答保存草稿”；真实适配器是否提问由缺失信息决定，不保证相同调用轨迹。本轮未调用真实模型。

运行 Worker 后，通过 `GET /v1/agent-runs/{run_id}` 的 `wait.question` 和 `wait.token` 查看待答问题；`GET /v1/agent-runs/{run_id}/waits` 查看等待与唤醒历史。回答示例：

```http
POST /v1/agent-runs/{run_id}/wake
Content-Type: application/json

{"wait_token":"<wait_token>","response":"先给三分钟独立思考，再进行两人讨论。"}
```

若是教师主动暂停仍在执行的根任务，使用下面的独立路径，再读取本次新 token 唤醒；不要对已经等待问题的任务重复暂停：

```http
POST /v1/agent-runs/{run_id}/wait
Content-Type: application/json

{"reason":"等待教师补充材料"}
```

普通暂停可附加未来的带时区 `wake_at`。模型提问没有定时自动回答路径。最终通过 `/artifact` 查看草稿，并通过 `/confirm` 提交该产物的 `content_hash` 完成独立的教师确认。

## 迁移与验收边界

当前代码要求数据库迁移 **0010**。该迁移新增课程记忆表、索引、范围约束和不可改写触发器，已有记忆历史时拒绝降级。模型问题复用 0009 的等待快照和唯一唤醒回执；执行池与新摘要协议不增加独立数据库列。

本轮只在名称以 `_test` 结尾的数据库内使用随机隔离 schema 进行迁移及测试；业务库仍为 **0006**，没有在本轮自动升级。部署新代码前需按部署流程备份、执行 `uv run --frozen alembic upgrade head`，再启动匹配版本的 API 与 Worker。不要在旧 schema 上直接启动新版 Worker。

验收覆盖实际工具循环摘要与重启、教师回答原样保留和一次配对、问答跨教师隔离、不可自动答题、记忆确认/替代/撤销/到期/来源校验、数据库冻结规则，以及执行池真实双槽重叠、动态子树 drain、once 上限和取消恢复。使用 fake 与 HTTP mock 验证工程协议；最新总数和完整回归结果见 [工程实施记录](IMPLEMENTATION_STATUS.md)，本文件不预写尚未完成的验收数字。
