## 与完整设计的有意简化

1. 当前为 M0 加部分基础可靠性。业务逻辑集中在 `domain.py`、`service.py`，执行逻辑在 `worker.py`；没有为十三个长期模块建立空框架。
2. `grading_items` 当前同时承载该固定工作流的权威执行状态。`attempts`、`model_calls`、`steps` 单独记录执行；以后有第二类长期任务时再抽出通用 `task_runs`。
3. 固定细则完整保存在不可变 JSONB 中，含稳定评分点 ID、语义版本、等级及分值；初评逐点使用关系表保存。尚未单独创建跨作业知识点与评分点版本注册表。
4. 草稿是只追加的快照，确认后不可改。修改规则通过新草稿和新确认版本完成，尚无交互式草稿编辑或自动起草。
5. 新细则可选择部分答案建立新批次并保留旧结果；当前仍对所选答案的全部评分点重新调用。**尚未实现只对变更评分点重评、重评影响计划或跨版本复用语义观察。**
6. 预览不保存导入 token 或文件原件。提交重新验证整个 JSON 数据，事务中全量接受或回滚；CSV/Excel 文件解析、逐行错误报告仍在后续阶段。
7. API 文档和演示脚本承担本阶段操作入口；教师前端、SSE、筛选排序与批量复核尚未实现。
8. 当前只有开发令牌身份，使用请求者所属课程与对象范围检查权限。正式登录、多教师协作授权、权限撤销与 RLS 尚未实现。
9. 当前没有自由模型工具循环、生成式规划、工具注册表、Hook 插件、子 Agent、长期记忆、pgvector、产品心跳或沙箱。
10. 没有取消 API、批次消费者取消传播、供应商特定限流分类或成本预算。已有总调用次数和尝试次数预算、调用超时，以及每次短事务检查和续租。假调用没有真实 token/金额计量。
11. 评估结果为 `succeeded` 仅表示结构化流程完成，仍需老师确认。弃判可以由老师选择等级；完全失败的答案要先重试，尚无独立的失败答案手工评分入口。
12. JSON 快照与 CSV 是本地下载能力；未实现对象存储、通知或学生成绩发布。

## 执行与一致性细节

单份答案执行状态：

```text
pending → running → succeeded
              └──→ retry_wait → running
              └──→ failed →（老师显式补充额度）pending
```

执行过程中断后，租约过期的 `running` 重新领取，增加 epoch；旧 attempt 标为 abandoned，未确定的调用标为 unknown。每次写检查点、分项结果或最终状态时，先锁任务行，再以数据库当前时间检查 owner、epoch、status 和租约。模型调用在数据库事务外执行。

默认单次调用超时 10 秒、租约 30 秒，自动尝试至多 3 次。每个评分点的初始总调用额度为 6 次，覆盖评估与证据两条步骤的有限重试；已消耗次数不会因重启或老师重试而清零。显式重试记录原因和新增加的额度。

批次保存自己的聚合状态与计数。更新先锁单项，再按固定顺序锁关联批次，锁后重新查询成员状态，避免用旧 ORM 缓存覆盖其他项目进度。全部结束时为 settled，另记录 all_succeeded / partial_failure / all_failed；确认状态独立保存。

初评、固定题目/答案/细则、步骤、复核、审计和导出快照由数据库触发器拒绝 UPDATE/DELETE。数据库管理员仍能变更结构；这不等于外部不可篡改审计系统。
