## 已确认的产品方向

自主实现 Agent Harness，以教学事务为中心，结合 Jev、生成式模型，以及有实际需要时加入的记忆、子 Agent 和心跳。

长期核心任务是：作业初评 → 老师处理争议并确认 → 班级共性问题 → 讲评和十分钟补练 → 学生订正 → 检查改善。还应逐步覆盖个人与班级学习分析、教学资料和经验、备课等工作。

“周五前完成……”是长期任务示例，不是本轮要建立的定时任务。本轮没有创建自动化。

## 已确认的首版

- 电子文本简答题。
- 老师提供题干及参考答案或课程材料，确认分项评分细则后冻结版本。
- 导入学生答案，绑定学生、题目及提交版本。
- 按独立评分点做语义初评；程序按已确认规则计算建议分数。
- 展示原答案、细则、候选等级、证据及建议分数，集中处理复核项。
- 保留老师修改与确认记录，导出区分已确认和待复核。
- 答案、题目、细则有版本；失败可单独重试；中断可恢复；重复请求不能生成重复有效结果；局部重评保留旧结果。

## 已确认的技术与数据约束

- PostgreSQL 是唯一业务主数据库，保存教学事实、身份与成员关系、评分、复核、订正、任务、操作回执、审计和长期知识。
- SQL 负责精确查询和统计；pgvector 后续按需用于相似检索，向量是可重建派生数据。
- 自主掌控模型调用、工具执行、上下文、预算、停止条件、权限、任务状态和恢复。
- 首版明确工作流优先；Claude Agent SDK 不默认承担核心。
- Jev 通过可替换适配器接入，同时保留普通生成式模型结构化初评基线。
- Jev Score 不直接作为成绩；confidence 不等于真实正确率；复核策略和收益必须实测。
- 学生历史不参与本次答案的独立评分，可用于后续补练和跟进。
- 一次老师修改不自动成为全局规则；规则变化形成新版本；经验保留来源、范围和确认状态。
- 学生答案、检索材料、工具结果是数据，不能改变权限或已确认规则。
- 不同难度、规则和覆盖范围下的原始分数变化，不直接解释为学习进步。

## 本次实施采用的选择

基于此前建议及“开始最小实现”的授权，采用 Python/FastAPI/Pydantic、SQLAlchemy/asyncpg/Alembic、PostgreSQL 任务表和独立 asyncio Worker。采用本地开发令牌身份，内部 JSON 导入先行，全部成绩须老师确认。它们是本轮具体实现选择，不代表用户已逐项锁定长期技术栈。

当前 `grading_items` 承载该固定工作流的执行状态；没有提前抽象通用 task runtime。评分细则是不可变 JSONB 快照，分项结果、步骤、调用、复核是关系记录。新细则支持选择部分答案新建批次，尚无只对变更评分点重评的复用计划。

2026-10-22 新增的 `agent_runs` 承担细则起草的持久工具循环，与 `grading_items` 的独立分项评分区分。仅开放两个代码注册工具，固定题目/老师/profile，保存草稿后等待老师确认；没有引入任意工具、Shell、长期记忆或多 Agent。上下文超限失败，不压缩替换教学事实。执行前登记模型调用，未知结果仍扣预算；不承诺外部调用恰好一次。

本轮选择 Jev 作为第一个真实适配器，是结合既定产品方向的实现选择；用户要求一个真实适配器，没有逐项指定 SDK、具体模型版本或计价。使用现有 HTTPX 发出单次请求，固定 `jev-x.y.z` 模型版本；配置快照哈希进入评估目标。API 与 Worker 配置需一致，更改后旧配置任务需要匹配的 Worker，不自动切换模型。

对照命令只写本地报告，不生成业务成绩；老师标注不发送给模型。`fake-v1` 只用于工程对照，普通生成式模型基线已按用户决定编写 DeepSeek 适配器。所有成绩继续人工确认，confidence 阈值只用于检查 Jev 误判，不自动放行；DeepSeek 不伪造概率或置信度。compare 仅测等级判断，不计入独立证据提取成本。
