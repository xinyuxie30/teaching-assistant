## 四、之前确定的方案（复述，未新增）

### 4.1 产品方向

以**教学事务为中心**自研 Agent Harness，而不是通用聊天助手。长期链路：

> 作业初评 → 老师处理争议并确认 → 班级共性问题 → 讲评与十分钟补练 → 学生订正 → 检查改善

后续逐步覆盖个人/班级学习分析、教学资料沉淀、备课。`EchoMind` 只借鉴思路，不作为业务底座。

### 4.2 首版范围（已确认）

- 电子文本**简答题**。
- 老师提供题干与参考答案/课程材料，**确认并冻结**分项评分细则版本。
- 导入答案，绑定学生、题目与提交版本。
- 按独立评分点做语义初评，**程序按已确认规则计算建议分**。
- 展示原答案、细则、候选等级、证据与建议分，集中复核。
- 保留老师修改与确认记录，导出区分**已确认**与**待复核**。
- 版本化、失败可单独重试、中断可恢复、重复请求不产生重复结果、局部重评保留旧结果。

### 4.3 技术与数据约束（已确认）

- **PostgreSQL 是唯一业务主库**，保存教学事实、身份、评分、复核、订正、任务、回执、审计与长期知识。
- SQL 负责精确查询统计；**pgvector 后置**，向量是可重建派生数据。
- 自主掌控模型调用、工具执行、上下文、预算、停止条件、权限、状态与恢复。
- **首版固定工作流优先**，Claude Agent SDK 不默认承担核心。
- Jev 走可替换适配器，同时保留**普通生成式模型结构化初评基线**（现为 DeepSeek）。
- **Jev Score 不直接当成绩**；confidence ≠ 真实正确率；复核策略与收益必须实测。
- 学生历史**不参与**本次答案的独立评分。
- 一次老师修改**不自动**成为全局规则；规则变化形成新版本。
- 学生答案、检索材料、工具结果只是**数据**，不能改变权限或已确认规则。
- 不同难度/规则/覆盖范围下的原始分变化，不解释为学习进步。

### 4.4 不可动摇的设计不变量

1. 所有成绩必须老师确认；`succeeded` 只表示流程完成，不等于可信成绩。
2. 模型只产出等级/证据，**分数由程序映射**；不信任模型自报总分。
3. 版本不可变 + 快照导出；后续改分不改写旧快照。
4. 写操作幂等；执行用租约 + epoch 隔离，晚到响应只能留审计。
5. **证据片段存在 ≠ 支持结论**，支持性必须老师判定。
6. **Agent 不能确认细则、不能改已确认规则、不能发布成绩**；确认动作只走原老师接口。

### 4.5 Agent 的既定方案

参考本机 Claude Code 源码**自研**，不引入第三方 Agent 框架：

- 第一个真实任务是**评分细则起草**（读题目 → 起草 → 存草稿 → 等老师 → 确认后完成）。
- 工具白名单只有 `read_question`、`propose_rubric`；代码内 Hook 只能收紧不能放宽。
- 默认模拟器 `fake-rubric-agent-v1`，DeepSeek `deepseek-rubric-agent-v1` 需显式选用。
- 预算：6 次模型 / 10 次工具 / 40,000 字符 / 300 秒；自动尝试上限 3。
- 状态机：`queued → running → waiting_teacher → completed`，另有 `failed / cancelled`。
- 老师确认细则时，在**同一事务**内写 `teacher_confirmed` 并结束 Agent 等待（已验证：`service.confirm_rubric` → `agent.service.rubric_confirmed`）。

### 4.6 迭代顺序与退出条件（原方案）

| 阶段 | 退出条件 |
| --- | --- |
| M0 | 一道题一批合成答案走完链路，重复请求与版本约束成立 |
| M1 | 故障矩阵强制场景全通过，而非只测正常路径 |
| M2 | 老师能自己完成一次导入—复核—导出，来源与状态可理解 |
| M3 | 契约通过；标注集评测覆盖误判、复核时间、成本与延迟 |
| M4 | 指标能追到确认结果，订正能追到原问题 |
| M5 | 有真实跨任务需求与对照验收后，再引入自主机制 |

## 五、审查发现

### P0 — 阻塞

**1. 业务库停在 `0003`，当前代码在真实库上跑不起来。**
实测：业务库无 `agent_runs` / `agent_events`，`model_calls` 无 `provider_fingerprint`。后果是 Agent 接口 500、DeepSeek 评分调用写 `model_calls` 因缺列失败。
处置：停 API/Worker → 备份 → `uv run --frozen alembic upgrade head` → `alembic current` 应为 `0005` → 跑一次演示与一个 fake agent run 冒烟。
注意：`0004` 只从旧检查点回填指纹，历史 `null` 不伪造，这是既定决定，不是缺陷。

### P1 — 重要风险

**2. 最新的 Agent 能力没有网页入口。** `frontend/src` 对 `rubric-agent` / `agent-runs` 零引用，只能通过 Swagger/curl 使用。老师看不到进度、草稿、预算消耗与失败原因，也就无法在页面完成"起草 → 审阅 → 确认"。

**3. 真实质量与成本仍是空白。** 唯一真实运行是 1 道题 + 2 份**合成**答案；无教师标注集、无 Jev/DeepSeek 配对比较。真实用量 13 次调用 / 15,418 input / 3,375 output，但未配单价，费用未知。因此不能据此选模型、定置信度阈值或宣称节省人工。

**4. Git 几乎没有提交，资产只在本机。** 远端 `origin/main` 只有 2 个初始提交；`agent/` 包、`0004`/`0005` 迁移、`deepseek.py`、`model_http.py`、`grading_runtime.py`、`execution_trace.py` 与全部新测试共 60 个变更未提交。硬盘故障或误删即全部丢失。

**5. 身份仍是开发令牌。** 无登录、令牌轮换、组织权限、RLS。跨老师隔离靠应用层校验（有测试覆盖），但不能对外部署。

### P2 — 已知边界与卫生问题

6. **导入仍只有逐份录入 + JSON 粘贴**；CSV/Excel 适配一直等真实样例，这是从 D 阶段挂到现在的待确认项。
7. **局部重评仍是"选定答案的全部评分点重跑"**，没有按变更评分点重评、也没有复用计划接口（文档已如实承认）。
8. **无 SSE**，改批次进度用有限轮询（指数退避、隐藏页暂停、401 停止）。Agent 有事件增量接口，批改批次没有 `/events`。属设计取舍，不是缺陷。
9. **前端主 chunk 1.02 MB / gzip 325 kB**，构建有体积警告；`PreparationPage` 已单独分包。
10. **文档口径小漂移**：`README.md` 仍写"24 张业务和执行表"，实际模型已是 **26 张**（`0005` 新增 2 张）；部分文档仍写 105 passed（最新 107）。不影响结论，但入口文档应同步。
11. **CI 的 `browser` job 从未在远端真实触发过**（本地运行记录存在）。GitHub 连接器当前不可用，无法核对 Actions 运行历史。

### 值得肯定的部分（审查确认，不是客套）

- 事务与并发设计是扎实的：短事务领取、模型调用不占事务、写回前校验 owner/epoch/status/租约、晚到响应只留审计。
- 审计不可变由数据库触发器兜底；导出用 REPEATABLE READ 物化快照。
- 幂等回执与业务写入同事务；同 key 异内容返回 409 有测试。
- CSV 导出对 `= + - @` 开头内容做公式注入防护。
- 契约严格（`extra="forbid"`、未知工具拒绝、重复调用 ID 拒绝、非有限数拒绝），且只在适配器层归一化供应商差异（如 `tool_calls.index`），不放松业务契约。
- 停止条件不可被扩展 Hook 放宽（`accepted = accepted and draft_id is not None`），取消即时 `epoch += 1` 隔离在途响应。
- 文档对"未验证/未执行"的标注非常克制，没有把桩验证写成真实调用——这在工程上很难得。
