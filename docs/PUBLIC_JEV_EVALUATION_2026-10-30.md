## 1. 评测对象与执行链路

本次评测围绕项目已经实现的作业初评链路：真实 DeepSeek 控制器读取教学任务、选择并调用工具，批改工具提交固定评分任务，真实 Jev 逐项判决，程序按冻结细则计算建议分数并保存到 PostgreSQL，最后由 Agent 收集批次结果。

```mermaid
flowchart LR
    A[公开题目与作答] --> B[真实 DeepSeek Agent Loop]
    B --> C[读取任务工具]
    C --> D[提交批改工具]
    D --> E[真实 Jev 判决]
    E --> F[程序计分与 PostgreSQL 提交]
    F --> G[收集结果工具]
    F --> H[离线对照人工标签]
```

执行入口为 `backend/tools/benchmark_public_grading.py`，数据适配入口为 `backend/tools/public_grading_data.py`，质量统计位于 `backend/tools/public_grading_metrics.py`。本次使用真实模型执行链路；单独的协议模拟负载及历史故障测试见 `docs/JEV_AGENT_ACCEPTANCE_2026-10-30.md`。

每个题目输入分片保持题干、参考材料和评分规则不变，最多包含 200 份作答。输入分片按波次提交；每波使用隔离的 PostgreSQL 测试 schema，保存观测与审计报告后清理。评测建立的是待复核初评，不自动确认学生成绩。

任务完成、初评保存和评分正确分别统计。Agent 成功收集一份含失败条目的报告，不自动意味着所有作答均完成评分；返回了建议分数，也不自动意味着与人工标注一致。

## 4. SAS-Bench 评分适配

可供模型读取的材料为 `question`、`reference`、`analysis`、题型对应的官方 `guideline`，以及按原有顺序拼接的 `steps[].response`。人工总分 `manual_label`、步骤得分 `steps[].label` 和错误标注 `steps[].errors` 仅留在离线评测侧。

现有 Jev 评分项最多支持 10 个有序等级。SAS-Bench 的题目满分与人工总分在本次版本中均为整数，满分最高 36 分。为完整覆盖总分范围，使用固定协议 `total-score-nine-point-bands-v1`：

设题目满分为 `T`、整份作答应得整数总分为 `S`。对每个下界 `b ∈ {0, 9, 18, 27}`，只建立满足 `b < T` 的区间，令 `w = min(9, T - b)`，该项贡献为：

```text
C_b(S) = min(max(S - b, 0), w)
S = sum(C_b(S))
```

每项等级为 `0..w`，最多 10 个。比如满分 20 分、应得 14 分时，三个区间贡献为 `[9, 5, 0]`。满分不超过 9 分时只有一项，直接预测原始总分。

| 每份作答的区间项数 | 作答数 |
| --- | ---: |
| 1 | 1,167 |
| 2 | 2,481 |
| 3 | 448 |
| 4 | 13 |

这个编码对目标整数总分可逆，且不依赖该样本的人工标签。但各项由 Jev 独立判断，预测结果可能互相矛盾。例如 `[5, 4, 0]` 虽然相加为 9 分，却不是任何一个 `S` 的有效区间编码。因此最终同时报告区间一致性、原始总分一致率，以及“总分正确且区间一致”的比例；直接总分组与多区间组分别报告。

**该协议评测的是本项目对人工总分的复现，不复现 SAS-Bench 原论文的步骤评分、CCS 或错误类型诊断。** 本次没有把人工分步得分直接变成模型可见评分点；SAS 的答案步骤并非项目中预先固定的独立内容评分细则。不同协议下的结果不能直接当成原论文排行榜成绩。

## 5. SemEval 标签适配

采用官方的 `correct` 对其他类别的二分类归约，协议为 `official-correct-vs-not-correct-v1`：

| 原始类别 | 评测标签 |
| --- | ---: |
| correct | 1 |
| partially_correct_incomplete | 0 |
| contradictory | 0 |
| irrelevant | 0 |
| non_domain | 0 |

模型只读取题干、全部官方参考回答和当前作答。多个参考回答可能是分别足以成立的替代表述，不能要求作答同时包含每一种表述。五类标签并不存在统一的数值高低顺序，本次不将它们映射成 0–4 分。

SemEval 的结果用于判断答案正确性的评测，SAS-Bench 的结果用于数值总分评测；不把两类任务混合为一个总体“评分准确率”。

## 7. 标签隔离与输入预检

数据适配层显式挑选可见字段，人工标签仅用于离线 `gold_levels`、源数据审计和结果比对。`teacher_confirmed` 是现有评测格式对人工标签的枚举值；`label_source` 同时写明是公开人工标注，不表示本项目教师已复核或批准业务成绩。

42 项数据适配测试已经通过，覆盖：

- 满分 `T = 1..36` 时每一个合法整数总分都能被无损编码和解码。
- 修改 `manual_label`、步骤分数和错误标签后，真实 `JevEvaluator.prepare()` 构建的请求保持不变。
- 越界标签继续保留输入且从质量对照中隔离。
- 数据样本与评测元数据一一对应，重复样本拥有不同来源身份。
- SemEval 只读取 Core、保留官方测试划分、排除训练调用，二分类映射正确。
- 小数分数会显式报错，不静默舍入。

修正分组后的 1,391 个分片、14,618 项请求结构已按冻结的 v2 配置重新完成离线预检，最大请求正文为 9,167 字符，配置上限为 20,000 字符；无输入超限、无文本截断、无因此排除的作答。审计产物为 `.local/datasets/public-grading/input-preflight-v2.json`；早期 v1 预检另保留在 `input-preflight.json`，未覆盖。预检只调用请求构造函数，不发送模型请求。数据适配器及其测试的 Ruff 与格式检查均通过。

## 8. 结果统计与执行记录

SAS 统计有效标签覆盖率、原分数完全一致率、端到端完全一致率、归一化绝对误差和偏高/偏低倾向，并按学科、题型与编码项数分组。SemEval 统计覆盖率、准确率、Macro-F1、混淆矩阵与类别支持量，保留官方 UA/UQ/UD 分组。

失败、尚未执行与拒判保留在覆盖率和端到端指标的分母中，不转换为零分。条件评分误差只针对实际产生有效分数的样本，必须同时展示覆盖率。源标签无效的 16 条仍计入工程完成率的 11,202 份输入分母。

独立分析对 SAS 加入“所有答案均给满分”基线，对 SemEval 加入“均判正确”和“均判不正确”两种常数基线。每种基线同时报告全部有效标签与 Jev 实际出分的同一子集，避免比较不同分母。较大分差固定定义为绝对误差至少达到题目满分的 20%；高置信检查固定为一份答案所有必要评分项的供应商 confidence 最小值至少 0.9。该阈值只用于观察经验误判，不作为自动放行规则。

95% 区间采用整题 bootstrap：在各数据集内按 `question_text_hash` 聚类，以固定种子 `20261030` 重采样 2,000 次，重算原本的答案级汇总指标，取 2.5% 与 97.5% 百分位。同题的所有答案、重复记录、失败和拒判一起抽样，无效人工标签仍不参与质量计算。这些区间仅描述当前公开题目集合的经验抽样不确定性；不涵盖学校与年级分布变化、标注误差、模型随机性或新的服务故障。供应商训练数据不可见，本次也未验证公开测试集污染。

工程审计涵盖任务状态、工具回执、评分版本和答案版本绑定、评分项完整性、重复有效结果、数据库提交结果及测试 schema 清理状态。模型耗时、评分耗时和完整 Agent 耗时分别报告。

工程对照沿用前轮已记录的实验参考线：完整流程及按时完成率至少 99%、可计分覆盖率至少 95%，本轮统一采用 120 秒窗口；任何分数、版本或唯一性不一致均单独判为完整性失败。这些是项目实验门槛，不是行业标准或生产 SLA。公开运行器返回“complete”只表示计划记录已完成终态采集，不代表质量或 SLO 达标。本次未预先设定公开数据准确率的通过线，因此质量指标如实报告，不事后选择阈值制造通过结论。

真实请求在发出前写入持久账本；失败或结果未知的请求不退回预算。已完整保存并清理的波次可跳过，避免恢复时重复付费调用。未完成波次需要先检查已有状态，不能自动重放。输出目录锁阻止两个运行器同时写同一结果目录。实际模型配置、并发槽数、波次大小、截止时间、输入摘要与请求预算以最终运行 manifest 为准。

本次执行使用单进程并发 Worker 和进程内 ASGI 提交。它可说明当前环境中的真实模型链路与落库表现；生产 HTTP 入口容量、长时间稳定性、多进程部署恢复和目标学校真实作业的适用性需要相应验收证据，不由本次公开数据结果自动推出。

原始轮发生 DeepSeek HTTP 402，官方定义为余额不足。中断记录、已完成波次与请求账本均保留；用户选择补充额度后继续真实控制模型。恢复时保留 1,837 条 Agent 已完成的结果，包括拒判和评分失败；9,365 条 Agent 未完成或尚未执行的记录进入续跑。续跑结果无论成功、拒判还是失败都作为该记录的最终结果，不回退选用旧分数。原始请求预留 3,670 次，续跑上限 26,330 次，合计仍受原定 30,000 次约束。[DeepSeek 错误码说明](https://api-docs.deepseek.com/quick_start/error_codes/)

本次故障也暴露出运行器把“已遍历但未建成批改项”计作完成的问题。已修正完成判定，并加入账户、认证和预算错误的波次熔断，遇到不可恢复问题不继续批量提交后续波次。实际 402 被分类为不可重试的 `provider_insufficient_balance`；未返回结果的请求继续保留预算预留。原始失败轮与恢复后的工程指标分别报告，不用续跑成功覆盖事故记录。

另外，原始轮的 PostgreSQL 日志证实两次 `evaluation_profiles_fingerprint_key` 唯一键冲突：多个执行者首次注册同一评分配置，原 SQL 只针对 ID 冲突执行幂等处理。第 9 波最终完成并通过结果审计；第 16 波另外遭遇余额中断，不能将其全部失败归因于配置注册。这是发生过的事务失败，不能因后续恢复而计为零错误。质量轮结束后，已修复为同时处理两个唯一键的插入冲突，再严格校验 ID、指纹与完整 manifest；不建立别名或改写历史。旧代码的冲突用例复现唯一键异常，修复后 3 项真实 PostgreSQL 回归通过，包括 3 轮各 8 个并发事务首次注册、配置不匹配拒绝和无部分批次残留。

### SemEval 的传输故障与覆盖偏差

**455/7093（6.41%）条 SemEval 样本因调用失败没有分数，另有 27 条弃权。** 455 条失败均经历了 3 条调用记录：453 条的失败码只有 `provider_transport_error`，2 条同时出现 `provider_transport_error` 与 `model_timeout`。这些是调用链路的传输/超时失败，不能当成 Jev 已完成的内容误判；同样不能从端到端分母中剔除。错误码本身不足以区分本地代理、网络与供应商服务的具体责任。
