## 2. 审查发现及收口事项

### R1：把关键本机检查沉淀为可维护的回归测试

`pyproject.toml` 的测试目录只有 `backend/tests`，CI 执行 `pytest -q`；`.local` 被忽略。因此，报告里的 30 项列表筛选、Jev 错误分类、弃判与重定向、部分复核导出检查不会自动随 CI 执行。27 个 pytest 用例与这些额外断言是不同统计口径，不能直接相加称为统一测试套件。

后续改代码时优先把有独立价值的场景迁到正式测试目录，复用隔离 schema 和 MockTransport，不把真实密钥、固定开发库 UUID 或收费模型请求带进默认回归。无需机械地把每条打印断言拆成一个测试。

目前 `.local/real_review_export.py:146` 仍写着：

```python
",pending,0.00,," in csv.text.replace("\r", "")
```

这个条件同时限制建议分数为零，不能单独说明“确认分数为空”。报告将该 FAIL 解释为断言问题，与源码相符。未来应使用 `csv.DictReader` 按稳定行身份选中记录，分别断言 `review_status` 与空 `confirmed_score`；不依赖另一列分数或整行子串。该脚本还依赖已有批次 UUID 和复核修订号，迁入回归时需要自建独立数据。

## 4. B 阶段的具体实现方案

沿用已有前端技术草案：React、TypeScript、Vite、Ant Design。新增 `frontend/`，保持 PostgreSQL、现有 API、Worker 与版本模型。

### 页面与接口

| 页面 | 主要操作 | 复用的后端能力 |
| --- | --- | --- |
| 作业与批次 | 选课程/作业，查看执行、失败和复核状态；翻页和筛选 | courses / assignments / grading-batches / grading-items 列表及批次详情 |
| 单份答案复核 | 同屏显示原答案、固定细则、候选等级和建议分；选择原文证据，逐点改判、写理由、查看历史 | item 详情、版本详情、追加 reviews |
| 导出记录 | 创建 working 或 confirmed_only 快照，明确已确认/待复核数量，下载已有快照 | 创建 exports、导出列表、JSON/CSV 下载 |

建议目录按业务页面划分，例如 `features/assignments`、`features/review`、`features/exports`；公共部分只抽 API 客户端、身份上下文、分页与证据定位工具。第一轮不抽通用 Agent 管理台。

### 必须保留的交互语义

1. **执行完成与老师确认分开。** `succeeded` 只代表初评完成；未确认分数不显示成零。模拟评估必须有明确标识，弃判显示待老师选择。
2. **复核以固定原文为准。** 原文按纯文本保留空白和换行；前端选区转换为 Unicode code point `[start,end)`，正确处理 emoji、重复片段和跨行文本，不把 JS UTF-16 下标直接提交。
3. **编辑已复核答案时加载最近一次老师决定。** 提交全部评分点及完整证据，不依赖可省略的 `citations` 自动继承老师上次选区；当前后端默认回退的是初评引用。
4. **并发冲突可见。** 发送 `expected_revision`，409 时保留本地编辑并展示服务器最新版本，由老师决定重新提交；不自动覆盖。
5. **重试与重复提交可区分。** 同一操作重发沿用同一幂等 key；修改请求内容后建立新 key。失败项按现有接口单独重试，显示原因和新增有限额度。
6. **进度先用有限轮询。** 页面可见时轮询，完成、切页或隐藏后停止，错误退避；本阶段不增加 SSE 依赖。
7. **下载的是固定快照。** 后续复核改分不改变已创建的下载记录；界面展示快照时间和确认范围。
8. **开发身份边界清楚。** 首先支持当前本机开发令牌，凭据只用于请求头和会话内状态；模型密钥继续留在后端。正式部署认证另立里程碑。

优先复用现有列表与详情契约。如页面确实缺少某项信息，再补相应读模型；不先增加新的数据库表或任务框架。前端开发代理统一转发 `/v1` 和健康请求到本机 API。

### B 阶段验收场景（由用户后续执行）

- 老师可找到待复核项，看见同一答案对应的题目与细则版本，逐点修改并确认。
- 中文、空行、emoji 和重复文字的引用能回到原答案，支持性判断及理由保存到复核历史。
- 两个页面同时修改时，后提交者能处理修订冲突，不丢失本地草稿。
- 网络重发不产生重复确认，失败任务不显示为已评分，弃判不会变成零分。
- 导出数量与确认范围对应，后续改分不改写旧快照。

## 5. C、D 阶段的约束与依赖

C 已编写名单/题目/细则录入和确认、逐份答案录入及按学号映射的 JSON 粘贴，预览通过后导入并建批次；CSV 或 Excel 文件格式仍等待实际样例。细则修改创建新草稿和确认版本；已有版本保持只读。现有局部重评范围是选定答案的全部评分点，界面不承诺只重跑变更的评分点。本轮没有运行这些新增代码，交接场景见作业准备说明。

D 的普通生成式模型也通过 `Evaluator` 返回合法等级及真实用量，不要求它伪造与 Jev 等价的概率分布或置信度。分数仍由程序计算。证据提取单独接入 `EvidenceExtractor`，不把证据存在直接解释为结论正确。

评测先确定一门学科、一个年级和少量代表性题目。可从 2–3 道题、每题约 20–30 份老师标注答案启动探索，但这只是采样建议，不是已确定的统计门槛。需覆盖部分得分、表述差异、答非所问、遗漏、矛盾与争议答案；划分调参与留出样本，约定严重误判标准。

报告分别计算分项/总分误差、严重误判与覆盖率；高置信度样本同样抽查。端到端对照还要统一证据流程、统计未知用量和重试，并记录老师实际复核时间。只有这些证据形成后，再决定模型组合、复核排序或自动证据功能的优先级。

待补输入仍是学科年级、真实题目与教师标注、普通模型供应商和预算、首个文件导入样例。C 可先用合成资料验收操作链路；D 的教学质量结论必须等真实标注和可追溯的评测结果。
