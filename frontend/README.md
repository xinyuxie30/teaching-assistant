# 教师工作台

React + TypeScript + Vite + Ant Design。对接现有 FastAPI，包含作业准备、课程/作业筛选、批次、单份答案复核和固定快照导出；作业准备页可让评分细则 Agent 起草草稿，答案导入支持逐份录入、JSON 与 CSV。

2026-10-22 现状：批次详情支持“班级学情”，可查看确认成绩的分布、分项表现、对应答案和老师理由；修改复核后返回分析重新计算。Agent 支持起草、历史恢复、反馈修订和确认前差异对照，手动或历史草稿也可直接修订。Harness v4 的通用 Agent 面板支持显示 `wait.question`、建议选项、原样提交自由回答及未知结果幂等重试；普通 rubric 任务仍不会主动提问，新增课程备课通过 API 使用，暂无专页。当前单测 **66 项**、类型与构建通过，浏览器原流程 **9/9 阶段、0 错误**。见 [Harness v4](../docs/HARNESS_V4_2026-10-22.md)、[班级分析交付](../docs/CLASS_ANALYSIS_2026-10-22.md) 与 [草稿入口交付](../docs/AGENT_DRAFT_ENTRY_2026-10-22.md)；历史阶段报告保留在 [工作台测试报告](../docs/FRONTEND_TEST_REPORT_2026-10-21.md)。

## 本机启动

保留根目录现有 `.env`。先按 [根 README](../README.md) 启动 PostgreSQL 和 API；需要执行待处理批次时启动 Worker，需要 Agent 起草或定时唤醒时再启动 `teaching-assistant harness-worker --concurrency 2`（兼容 `agent-worker`，默认单槽）。新版服务需迁移到 `0010`；本轮仅迁移隔离测试 schema，已有业务库仍为 `0006`，须按根 README 备份升级后启动。

建议使用 Node.js 24.16.0（CI 的固定版本），包管理使用 npm，依赖锁定于 `package-lock.json`。`package.json` 的 Node engines 同时考虑 Vite 和测试环境要求。

在独立 PowerShell 终端中：

```powershell
Set-Location .\frontend
npm.cmd ci
npm.cmd run dev
```

打开 [本地工作台](http://127.0.0.1:5173)，填入后端 `.env` 中的 `TA_DEV_API_TOKEN`。这里只接受开发访问令牌；模型密钥留在后端配置中。

前端通过同源 `/v1` 请求，由开发服务器代理到 `http://127.0.0.1:8000`。后端使用其他端口时，在启动 Vite 的终端设置：

```powershell
$env:TA_API_ORIGIN = 'http://127.0.0.1:8001'
npm.cmd run dev
```

`TA_API_ORIGIN` 只配置开发/预览代理，不会被嵌入浏览器代码。无需开放跨域或在前端保存模型配置。前后端开发端口均默认绑定回环地址。

## 使用流程

准备新作业时，从侧栏“作业准备”进入：新建课程/班级/名单 → 创建作业 → 保存题目版本 → 起草并确认评分细则（可手动，也可“用 Agent 起草”后检查并确认） → 预览并导入答案（逐份、JSON 或 CSV） → 选择具体答案版本及评估配置建批次。细则确认后需明确选用，默认模拟器；真实模型由老师显式选择。Agent 只保存未确认草稿，不能确认细则或成绩。详细格式与版本语义见 [作业准备说明](../docs/ASSIGNMENT_PREPARATION.md)，Agent 见 [Agent 说明](../docs/RUBRIC_AGENT_2026-10-22.md)。

已有批次从“作业与复核”进入：

“班级学情”标签显示本批次固定题目/细则下的当前老师确认结果。点击“查看本项未得满分答案”可以阅读对应老师理由并回看原答案；未确认和失败记录不会计入成绩统计，全部或待复核答案可通过“分析答案范围”筛选。若其他页面更新了复核，明细会提示刷新分析，不沿用过期人数。

1. 选择课程、作业或执行状态，打开已有批次。课程和作业下拉列表支持“加载更多”；列表采用游标翻页。
2. 默认进入待复核答案列表；可切换全部、已确认和失败项。
3. 打开一份答案，左侧查看原答案和题目，右侧按固定细则逐点选择等级、证据判断和理由。
4. 在原文中选取片段，选择评分点并加入引用。“定位原文”可重新选中已有引用。没有自动证据时，由老师补选或明确使用人工判断/表达缺失。
5. “确认全部评分点”追加一次复核。服务器计算最终确认分数；未确认结果保留空值。页面会显示历史决定。
6. 返回批次的“导出快照”，选择工作汇总或仅已确认，创建快照后下载 CSV 或 JSON。后续改分不修改旧快照。

初评失败的答案可填写原因，增加有限的尝试次数和调用额度后单独重试。真实模型重试可能产生费用，页面会在提交前说明。

修改已保存的细则时，在本题的“已保存草稿”中打开目标，点击“让 Agent 修改这份草稿”，核对所选来源并填写修改意见，再生成新版。手动草稿和已确认草稿都支持；原稿保留，新版在对照检查后单独确认。只打开入口不会调用模型。来源及意见按当前页面会话保存，响应丢失时先“重试同一次提交”。

## 本阶段边界

- 已补准备流程网页入口；名单目前随新课程/班级一次录入，没有向已有课程追加班级或调整名单的页面。答案支持逐份录入、JSON 粘贴和 CSV 粘贴/文件（UTF-8，首行表头，2 MB 上限）；CSV 在浏览器内映射到固定名单，服务器仍重新校验并原子提交。Excel 待真实样例。
- 开发令牌、编辑草稿和幂等提交标识仅存在当前页面会话。站内切页保留；刷新、关闭页面或退出会清除。未保存编辑会触发离开提示。
- 请求结果未知时锁定相应写操作，可“重试同一次提交”，复用原 key 和请求内容。先解决未知结果再退出，不能把浏览器刷新当作持久恢复。
- 遇到修订冲突会保留编辑，展示最新老师决定；由老师选择载入最新内容，或比较后在最新修订上继续编辑，不自动重提。
- 采用可见页面轮询和错误退避，无 SSE、后台推送、持久前端草稿、URL 深链接或正式登录。
- 文本全部按纯文本渲染。原答案不插入 HTML 高亮；原生选区用于定位，提交的索引转换为 Unicode code point。

## 检查方式与当前结果

下表为 2026-10-22 本轮实际执行的结果；历史阶段记录保持不变。

在 `frontend/` 下：

```powershell
npm.cmd ci
npm.cmd test
npm.cmd run typecheck
npm.cmd run build
npm.cmd run preview
```

| 检查 | 2026-10-22 结果 |
| --- | --- |
| `npm test` | **55 passed / 8 files** |
| TypeScript 类型检查 | 通过（随 `npm run build` 执行） |
| `npm run build` | 通过；入口 22.85 kB / gzip 9.18 kB，antd 754.58 kB / gzip 243.64 kB，**无体积警告** |
| 浏览器回归 | **1 passed，8/8 断言阶段，0 浏览器错误**（含来源选择及实际差异展示） |
| 作业准备全链路 | 课程/名单 → 作业 → 题目 → Agent 修订及确认 → 手动草稿修订与对照 → 原稿确认 → 导入 3 份版本 → 建批次 → 复核 → 两种导出 |

`build` 自带类型检查；`typecheck` 可独立定位类型问题。`preview` 使用 Vite 的预览端口，仍需运行 API，仅用于本机查看构建产物。

测试使用 Vitest + jsdom，覆盖原文引用、最近复核草稿、空引用显式提交、弃判、幂等重发、409、响应读取超时、Agent 状态/预算/事件映射，以及 CSV 解析与名单映射；不连接数据库或真实模型。

正式浏览器回归在独立的 `e2e/` 包运行，使用同一份新建合成作业串起准备、模拟初评、复核与两种范围的 CSV/JSON 下载，断言实际业务内容，详见 [执行与产物说明](e2e/README.md)。CI 已加入 `agent-worker`，既有提交的三个 job 已通过；本次未提交增量尚未运行 CI。浏览器并发冲突、失联重试、跨页恢复、键盘与真实拖拽仍需后续验收。

技术参考：[Vite 指南](https://vite.dev/guide/)、[Ant Design React 文档](https://ant.design/docs/react/introduce/)、[React Effect 生命周期](https://react.dev/reference/react/useEffect)。
