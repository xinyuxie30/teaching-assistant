## 本机启动

保留根目录现有 `.env`。先按 [根 README](../README.md) 启动 PostgreSQL 和 API；需要执行待处理批次时启动 Worker。已有 `0003` 的数据库本次无新增迁移。

建议使用 Node.js 24.16.0（CI 的固定版本），包管理使用 npm，依赖锁定于 `package-lock.json`。`package.json` 的 Node engines 同时考虑 Vite 和测试环境要求。

在独立 PowerShell 终端中：

```powershell
Set-Location 'D:\PyChram_project\面向教师的全面助手\frontend'
npm.cmd ci
npm.cmd run dev
```

打开 [本地工作台](http://127.0.0.1:5173)，填入后端 `.env` 中的 `TA_DEV_API_TOKEN`。这里只接受开发访问令牌；模型密钥留在后端配置中。

前端通过同源 `/v1` 请求，由开发服务器代理到 `http://127.0.0.1:8000`。后端使用其他端口时，在启动 Vite 的终端设置：

```powershell
$env:TA_API_ORIGIN = 'http://127.0.0.1:8001'
npm.cmd run dev
```

`TA_API_ORIGIN` 只配置开发/预览代理，不会被嵌入浏览器代码。无需开放跨域或在前端保存模型配置。前后端开发端口均默认绑定回环地址。

## 使用流程

准备新作业时，从侧栏“作业准备”进入：新建课程/班级/名单 → 创建作业 → 保存题目版本 → 起草并确认评分细则 → 预览并导入答案 → 选择具体答案版本及评估配置建批次。细则确认后需明确选用，默认模拟器；真实模型由老师显式选择。详细格式与版本语义见 [作业准备说明](../docs/ASSIGNMENT_PREPARATION.md)。

已有批次从“作业与复核”进入：

1. 选择课程、作业或执行状态，打开已有批次。课程和作业下拉列表支持“加载更多”；列表采用游标翻页。
2. 默认进入待复核答案列表；可切换全部、已确认和失败项。
3. 打开一份答案，左侧查看原答案和题目，右侧按固定细则逐点选择等级、证据判断和理由。
4. 在原文中选取片段，选择评分点并加入引用。“定位原文”可重新选中已有引用。没有自动证据时，由老师补选或明确使用人工判断/表达缺失。
5. “确认全部评分点”追加一次复核。服务器计算最终确认分数；未确认结果保留空值。页面会显示历史决定。
6. 返回批次的“导出快照”，选择工作汇总或仅已确认，创建快照后下载 CSV 或 JSON。后续改分不修改旧快照。

初评失败的答案可填写原因，增加有限的尝试次数和调用额度后单独重试。真实模型重试可能产生费用，页面会在提交前说明。

## 本阶段边界

- 已补准备流程网页入口；名单目前随新课程/班级一次录入，没有向已有课程追加班级或调整名单的页面。答案支持逐份录入和 JSON 粘贴，文件导入格式待定。
- 开发令牌、编辑草稿和幂等提交标识仅存在当前页面会话。站内切页保留；刷新、关闭页面或退出会清除。未保存编辑会触发离开提示。
- 请求结果未知时锁定相应写操作，可“重试同一次提交”，复用原 key 和请求内容。先解决未知结果再退出，不能把浏览器刷新当作持久恢复。
- 遇到修订冲突会保留编辑，展示最新老师决定；由老师选择载入最新内容，或比较后在最新修订上继续编辑，不自动重提。
- 采用可见页面轮询和错误退避，无 SSE、后台推送、持久前端草稿、URL 深链接或正式登录。
- 文本全部按纯文本渲染。原答案不插入 HTML 高亮；原生选区用于定位，提交的索引转换为 Unicode code point。
